# Code Review（团队代码审查）

## Overview

按团队审查规范对代码/PR 执行结构化审查：六维清单逐项检查 → 🔴🟡💭✅ 分级评论（文件:行号 + 根因 + 建议）→ 输出审查报告 → 识别可沉淀案例。审查目标是**提升团队能力**（每个评论都教东西），不是找茬。

完整规范见 `references/standards.md`（v1.0，含流程/模板/度量）；真实踩坑案例见 `references/case-library.md`（审查时优先对照）。

## 触发与输入

| 用户说法 | 动作 |
|---------|------|
| "审查这个文件/这段代码" | 读取指定文件 → 全量审查 |
| "审查这个 PR / review PR" | 团队仓库（github.com/hucaidab/-ai）用 `gh pr view/diff` 取改动 → 只审改动行 |
| "检查代码质量" / "看看有没有问题" | 对当前工作目录最近改动或指定目录做一次快审 |
| "按规范审查 xxx" | 严格按 references/standards.md §3 清单逐项过 |

## 审查流程（5 步）

```
① 取代码   读文件 / gh pr diff（PR 只审改动行 + 周边上下文）
② 跑机械检查  scripts/quick-lint.mjs（语法）+ scripts/check-secrets.mjs（密钥扫描）
③ 清单审查  按六维清单逐项过（下节），命中案例库的优先对照
④ 分级评论  按 §评论格式 输出：🔴 阻塞 / 🟡 建议 / 💭 可选 / ✅ 表扬（≥1）
⑤ 交付     输出审查报告：汇总 + 问题清单 + 修复建议 + 是否建议新增案例
```

## 六维审查清单（精简，完整版含检查项编号见 references/standards.md §3）

| 维度 | 核心检查点 | 常见 Blocker |
|------|-----------|-------------|
| **正确性** | 边界（空/0/超长/重复/并发）；错误路径 try/catch + 回滚；幂等；异步竞态/未 await/监听泄漏；数据一致性（单一数据源） | 竞态、引用失效、状态不回滚 |
| **安全** | 路径穿越；敏感文件暴露（llm.config.json/.env/.git）；注入（SQL/Shell/XSS）；HTML/SVG 输出转义；密钥硬编码；写删操作权限 | 路径拼接、明文密钥、未转义输出 |
| **可维护** | 命名见名知义；单一职责；DRY（3 处以上才抽）；"为什么"注释；死代码；文件边界/无循环依赖；**是否破坏调用方契约** | 契约破坏 |
| **性能** | 循环内 IO/重计算；O(n²) 陷阱；前端全量重渲染/重复绑事件/缺防抖；资源释放；**先度量再优化** | 交互卡顿元凶（全量重建） |
| **测试** | 主路径+边界+错误路径覆盖；**已修 bug 的回归用例**；测试是否真实（模拟事件可能假阳性）；测试数据环境无关（禁写死 /tmp/绝对路径）；CI 全绿 | 模拟≠真实、无回归用例 |
| **工程治理** | **零技术债**（禁"先用着后面重构"）；**妥协申报**（未申报妥协=违规，必须写入 compromise-register.md）；**单一数据源**（数据不分叉）；架构一致性（不引入分叉）；文档同步 | 未申报妥协、架构分叉 |

## 评论格式

```
[级别] **类别: 主题**
文件:行号：<具体问题>

**为什么：** <根因/影响/后果>

**建议：**
- <方案1>
```

示例：

```
🔴 **Security: 路径穿越**
preview-server.mjs:312：文件名直接拼进 path.join，未校验。

**为什么：** 攻击者传 ../../llm.config.json 可读取 API 密钥（案例库案例1）。

**建议：**
- 加敏感文件黑名单（llm.config.json/.env/.git → 403）
- path.resolve 后校验仍在根目录内
```

```
✅ **Praise: 回归意识**
test-core.mjs:188：给 END 关键字 bug 加回归用例——这类"修完就忘"的 bug 最容易复发，锁死它很专业。
```

## 反模式（禁止）

- ❌ 只给 "LGTM/👍" 没有具体评论（等于没审）→ 至少 1 条具体观察
- ❌ 挤牙膏式追加评论 → 一次性给全
- ❌ 用风格偏好（引号/缩进）阻塞合并 → 交给 linter，人只审逻辑
- ❌ 只批评不表扬 → 强制 ✅ ≥1
- ❌ 评论不落到文件:行号 → 必须可定位

## 团队原则对齐（审查必查）

1. **零技术债**：发现"最小可用版/临时方案/复制粘贴改造"→ 🔴，要求一次做对
2. **妥协申报制**：确需妥协 → 必须已告知用户 + 写入 `compromise-register.md`；未申报 = 🔴
3. **单一数据源**：产出与管理系统读同一份数据；发现数据分叉 = 🔴

## 脚本用法

```bash
# 批量语法检查（快速拦语法错误）
node scripts/quick-lint.mjs <文件或目录...>

# 密钥/敏感信息扫描（提交前必跑，命中 exit 1）
node scripts/check-secrets.mjs <文件或目录...>
```

## 案例库更新

审查中发现**新类型问题**（不在 references/case-library.md 中的模式）→ 审查报告末尾建议新增案例，格式：现象 / 根因 / 教训 / 审查拦截点。每周复盘挑 1 个最典型的正式入库。
